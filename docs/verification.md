## 모바일 오디오 시작 및 복구

- 확인된 경로: 첫 터치 시작에서만 오디오를 재개했고, 응답이 없는 `resume()`에는 제한 시간이 없었다. 숨겨진 탭에서 돌아왔을 때도 이전 출력을 재사용했다. 사용자 기기에서 실제로 어떤 경로가 발생했는지는 불명.
- 정상 입력은 기존 음색·박자로 즉시 처리한다. 누를 때와 달리 활성화 권한이 부여될 수 있는 터치 종료에서도 재시도한다. 1.5초 동안 응답이 없으면 같은 탭의 다음 입력이 새 출력을 사용한다. `running`이라도 입력 사이에서 렌더 시간이 700 ms 이상 멈춰 있으면 재생 연결을 교체한다. 숨김·페이지 이탈·방문 기록 복원 시에는 옛 입력과 출력을 해제하며 곡을 자동 재시작하지 않는다.
- 설정에서 출력을 다시 연결하고 저장된 음량으로 짧은 시험음을 재생할 수 있다. 음량이 0이면 해당 설정을 그대로 보존하고 알려 준다.
- 격리된 Chrome 탭에서 첫 `resume()`이 끝나지 않도록 주입한 결과, 이전 출력 신호는 0이었고 재생 상태가 정상 종료됐다. 같은 탭의 두 번째 재생 요청에서 실제 Web Audio 출력 노드 신호의 피크 약 0.264를 측정했다. 페이지 이탈·복원 이벤트를 전달해 자동으로 소리가 재시작되지 않는지, 설정 시험음이 새 출력에서 다시 약 0.264까지 발생하는지도 확인했다. 실물 휴대폰 스피커나 Instagram 내장 브라우저에서 들리는 소리를 측정한 것은 아니다.
- 근거: [사용자 활성화의 입력 이벤트](https://html.spec.whatwg.org/multipage/interaction.html#activation-triggering-input-event), [Web Audio의 resume 대기 동작](https://www.w3.org/TR/webaudio-1.0/#dom-audiocontext-resume), [복귀 후 멈춘 렌더 시간에 대한 WebKit 보고](https://bugs.webkit.org/show_bug.cgi?id=263627).
